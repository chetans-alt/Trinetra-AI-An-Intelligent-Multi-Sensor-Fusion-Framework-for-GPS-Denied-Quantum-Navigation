# Phase 10 — ROS 2

Source: trinetra_phase10_ros2. ROS 2 is an **adapter**, not the architecture (see [architecture.md](architecture.md)). It comes after the Python core is validated offline (CLAUDE.md: ROS 2 and C++ come after the finished ESKF).

## Why ROS 2

Decentralised DDS discovery (no roscore), configurable QoS, real-time friendly, SROS2 security, multi-platform.

## Building blocks

| Concept | Project use |
|---|---|
| Node | one per sensor/module |
| Topic | `/imu`, `/mag`, `/gps`, `/baro`, `/odometry/filtered` |
| Service | calibration, reset filter, get health |
| Action | navigate to pose (optional) |
| Parameter | Q, R, rates, window sizes, frame ids |
| Launch file | bring up the stack |
| Lifecycle node | deterministic bring-up |
| Composition | latency-critical nodes in one process on Jetson (zero-copy) |
| tf2 | frame transforms |

**QoS:** high-rate sensor streams best-effort, keep-last (`SensorDataQoS`); TF and commands reliable. QoS mismatch = silent no-messages.

## TF tree (REP-105)

`map → odom → base_link → {imu, mag, gps, baro}_link`. map→odom = discrete jumps where global corrections (magnetic map match, GPS) enter; odom→base = smooth, continuous; base→sensor = static mounts. Composition `T_imu^map = T_odom^map T_base^odom T_imu^base`; inverse `[[Rᵀ, −Rᵀt],[0,1]]`.

## Localization

`robot_localization` provides EKF and UKF nodes fusing Imu, Odometry and PoseWithCovariance; `navsat_transform` adds GPS into map frame. Project: robot_localization-style fusion + a **custom magnetic map-match node publishing an absolute pose** (the GPS-denied counterpart of navsat_transform) + TF2. Nav2 (AMCL, costmaps, planners, behaviour trees) is optional downstream.

## Node graph and interfaces

| Node | Subscribes | Publishes |
|---|---|---|
| Sensor nodes | hardware | `/imu /mag /gps /baro` |
| Sync | raw topics | `/synced` |
| Signal / feature | `/synced` | `/features` |
| AI nodes | `/features` (+ `/innovations`) | `/clean /bias /anomaly /confidence` |
| Fusion (EKF) | clean + corrections + confidence | `/odometry/filtered`, TF odom→base |
| Localization | fused state + `/mag_fix` | TF map→odom |
| Nav / trajectory | pose | `/plan /trajectory` |

Services `/calibrate_mag`, `/reset_filter`, `/get_health`; action `/navigate_to_pose`.

Workspace packages: `trinetra_bringup`, `trinetra_msgs` (Health, Confidence), `trinetra_sensors`, `trinetra_pipeline`, `trinetra_ai`, `trinetra_fusion`, `trinetra_nav` (optional), `trinetra_description`, `trinetra_sim`. Nodes import the core; they never re-implement it.

Dataset replay: a node/script that publishes each dataset as `/imu /gps /mag` so the same stack runs on recorded data and live hardware. Mask `/gps` to force denial.

## Debugging checklist

`ros2 topic hz` (rates), `ros2 topic echo` (sanity), `ros2 run tf2_tools view_frames` (connected tree), RViz2, record → replay to reproduce bugs, QoS compatibility. Mistakes: QoS mismatch, rootless TF tree, wrong frame_id, unsynced timestamps, noise-free sim.

## Contributions this enables

Open modular GPS-denied ROS 2 package set; custom magnetic map-match localization node; edge-deployed AI fusion benchmarked on Jetson; Gazebo GPS-denied world + MCAP benchmark.

## Derivations to know

Transform composition and inverse; why map→odom jumps but odom→base is smooth; QoS choice per link; fusing the map-match pose via robot_localization; mapping Phase 7 fusion onto the node graph.
